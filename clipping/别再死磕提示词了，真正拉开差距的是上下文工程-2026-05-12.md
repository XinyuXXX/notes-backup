## 核心命题

**提示词工程是语法。上下文工程是基础设施。基础设施永远胜过语法。**

那些真正能工作的 AI 系统——能记住偏好、访问数据、稳定遵守规则、日复一日产出可靠结果——构建者并没有在写更厉害的提示词，他们在工程化更好的上下文。

上下文工程，是设计、组织和管理 AI 模型在生成回答时能够访问的准确信息。它包含提示词周围的一切：模型能读取的文件、从之前会话带来的记忆、能调用的工具、约束行为的规则、校准输出的示例。

> 再完美的提示词，如果放在糟糕设计的上下文里，每次都会产出平庸结果。普通的提示词，如果放在完美设计的上下文里，每次都会产出出色结果。

## 上下文的三层结构

每一次 AI 交互都有三层上下文，而大多数人只用到了其中一层：

- **第一层：即时上下文**——提示词本身（99% 的人停在这里）
- **第二层：会话上下文**——上传文件、对话历史、系统指令（大多数人部分使用，但没有刻意设计）
- **第三层：持久上下文**——跨会话保留的知识：记忆系统、上下文文件、知识库、保存的偏好（**最大的杠杆在这里**，几乎没有人真正用好）

你的提示词只是一种食材。上下文是整间厨房。

## 四个核心文件

每次会话开始时加载这四个文件，模型就会从通用助手变成具备上下文意识的协作者：

1. **身份文件**：你是谁、做什么、专业能力、背景、沟通风格——给 AI 的「入职文档」
2. **受众文件**：你在为谁创作——人口特征、心理特征、知识水平、痛点、目标、使用语言
3. **标准文件**：什么才算好——质量标准、格式偏好、语气指南、反模式、优秀作品示例
4. **项目文件**：当前正在做什么——现阶段目标、活跃项目、近期决策、开放问题、截止时间（动态层，按周或按月变化）

每个文件控制在 2,000 词以内，确保能轻松放进上下文窗口。

## 动态上下文加载

把整个知识库塞进每一次对话是 token 浪费，会稀释模型注意力。动态加载的意思是给模型提供当前具体任务所需的正确信息：

| 任务类型 | 加载的上下文 |
|---|---|
| 写作任务 | 身份文件 + 受众文件 + 标准文件 + 最佳内容示例 |
| 分析任务 | 身份文件 + 项目文件 + 原始数据 + 既往分析 |
| 研究任务 | 项目文件 + 研究方法文档 + 既有研究 |
| 策略任务 | 全部四个文件 + 竞争格局文档 + 行业数据 |

## 记忆系统的三种方法

1. **手动记忆文档**：维护一份持续更新的文档，记录关键决策、学习和偏好，每次会话开始时粘贴相关部分——适合个人和小规模工作
2. **结构化知识库**（中级）：用 markdown 文件夹结构组织（Obsidian 适合）。Claude Code 可直接从文件系统读取这些文件
3. **向量数据库 + RAG**（高级）：嵌入到向量数据库，自动检索最相关上下文，可扩展到数千份文档——生产级 AI 系统的方式

进化路径：先从手动记忆文档开始 → 超过 20 份文档升级到结构化知识库 → 超过手动可管理范围再进入向量数据库。

## MCP：把上下文连接到工具

没有工具的上下文，是没有双手的知识。MCP（Model Context Protocol）让富上下文 AI 模型能根据它知道的事情采取行动。

**上下文优先，工具随后**的集成模式：
- 系统提示词建立上下文（模型是谁、知道什么、遵循什么标准）
- MCP 服务器提供能力（网页搜索、文件访问、数据库查询、API 集成）
- 任务提示词把二者连接起来

上下文 + MCP = 模型从**顾问**变成**操作者**。

## 六周课程框架

1. 审计上下文层，创建第一个上下文文档
2. 设计四文件上下文架构
3. 掌握动态上下文加载规则
4. 构建跨会话持久记忆系统
5. 用 MCP 连接工具和数据源
6. 包装成生产系统并规模化（企业级：每个项目 $5,000–$25,000）

## 结论

提示词工程是 2024 年的技能。上下文工程是 2026 年以及之后的技能。
