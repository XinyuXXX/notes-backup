## 核心论点

**定时调度是 Agent 走向自主运行的最主要触发形态**——让 Agent 按既定时间规划定时运行，使其成为能自行"打卡上班"的数字员工。

主流商业产品均将定时调度放在付费档位（ChatGPT Tasks / Manus Tasks / Claude Code Routines / Gemini Scheduled Actions），这意味着它已不是锦上添花的小功能，而是 Agent 从「工具」升级为「岗位」的关键基础设施。

## 开源 Agent 定时任务的五大痛点

1. **无高可用**：任务配置存本地文件，机器/磁盘故障即丢失；单进程架构，进程挂了服务即中断
2. **运维成本高**：每个 Agent 独立控制台，企业有 1000 个 Agent 时任务管理极其分散
3. **权限管理弱**：不支持任务级别权限，无法给不同用户配置不同任务权限
4. **可观测能力弱**：执行记录无分页、无搜索过滤，Hermes Agent 甚至没有任务执行记录
5. **资源利用率低**：定时任务内嵌在 Agent 进程里，Agent 必须常驻——一天只跑一次的任务也得 24 小时开机

## 平台化解法：从 Agent 内抽离调度层

核心思路：**把定时调度从每个 Agent 内部抽离出来，由任务调度平台统一管理**。

> 如果每个定时运行的 Agent 是数字生产力一员，AI Agent 任务调度平台就是面向 Agent 的「OA 系统」。

关键能力：
- **高可用调度**：云存储持久化 + 分布式多可用区 + 自动重试/超时告警；失败后下个周期仍按计划触发，杜绝"一次失败、永久停摆"
- **统一管控**：所有 Agent（自研/百炼/Dify/OpenClaw/Hermes）的定时任务收拢到一个控制面；Prompt 版本化管理
- **精细权限**：RAM 权限管理 + Token 配额管理（按应用设预算，避免 Agent"烧钱失控"）
- **全链路可观测**：监控大盘 / 执行历史 / 日志服务 / 链路追踪（含 Tools 调用）/ 报警监控
- **弹性伸缩降本**：对接 Sandbox 弹性伸缩，任务触发前预热拉起，无任务时缩容到 0

## 会话管理三模式（关键设计决策）

| 模式 | 行为 | 适用场景 |
|---|---|---|
| 指定会话 | 任务跑在某个主会话里，共享该会话记忆 | 需要与主对话共享上下文 |
| 任务隔离 | 不同任务隔离不同会话，同一任务每次执行共享记忆 | 任务级记忆累积（推荐） |
| 调度隔离 | 每次调度新起会话，无任何上下文记忆 | 不推荐（会话撑爆风险） |

## 自进化定时任务

在任务级别会话隔离模式下，系统采集每次执行的日志/tracing/结果/错误信息，共享该任务所有历史上下文。任务初期运行失败或效果不好时，可根据历史信息**动态调整 prompt 和参数**，让任务越跑效果越好——真正的自进化 Agent 定时任务。

## 分布式任务模型

支持将一个大任务拆分成多个小任务，分给不同 Agent 节点并行执行（分片模型），加快执行速度——与 Multi-Agent 架构天然契合。
