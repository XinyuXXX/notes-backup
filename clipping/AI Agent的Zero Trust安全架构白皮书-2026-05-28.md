> **核心主张**：AI Agent 引入了自主性和工具访问，使传统边界安全彻底失效。Zero Trust 的三条原则（永不信任、假设已被攻破、最小权限）是 Agent 安全的基础。AI 正在把漏洞到利用的时间从几个月压缩到几小时，"基本功足够扎实、从第一天就按'假设已被攻破'设计"的组织才能赢。

---

## 为什么 AI Agent 需要 Zero Trust

前沿 AI 把漏洞到利用的时间窗口从几个月压缩到几小时，边际成本按美元计。模型现在就能找到传统工具和人工审计连年都没发现的严重漏洞。

Agent 系统带来双重影响：
1. Agent 运行的基础设施和其他资产一样暴露在 AI 加速的攻击面前
2. Agent 本身引入了自主性——能解读目标、选择工具、执行多步操作。传统访问控制挡不住 Agent 滥用**合法权限**

**最适合应对的组织，不是 AI 最先进的那些，而是基本功足够扎实（AI 辅助扫描一上来找不到几个 bug）且从第一天就按"假设已被攻破"设计 Agent 部署架构的。**

---

## 三条核心原则

1. **永远不信任，始终验证**：每个访问请求都必须认证和授权，无论来源。内网请求和外部 IP 接受同等审查。

2. **假设已被攻破**：设计系统时就预期攻破会发生。精力集中在限制攻击者能造成的损害，而非防止入侵。按身份分段，实施细粒度访问控制。

3. **最小权限**：只授予完成特定任务所需的最低访问权限。控制单次攻破的爆炸半径（blast radius）。

### 设计检验标准：不可能，还是只是麻烦？

评估任何控制措施时问一个问题：**这是让攻击变得不可能，还是只是更麻烦？**

那些价值来自"摩擦"的措施——额外跳板、速率限制、非标端口、基于短信的 MFA——在面对能大规模碾过麻烦步骤的对手时大幅失效。Agent 化的攻击者有无限耐心，每次尝试成本接近零。

能通过测试的控制：硬件绑定凭证、会过期的 token、密码学身份、**根本不存在的网络路径**（而不是不方便的路径）。

> **优先选择移除能力的控制，而不是限流能力的控制。**

## Agent 系统有什么不同

| 特性 | 安全含义 |
|---|---|
| **无人值守执行** | 被操控的 Agent 能以机器速度造成伤害 |
| **工具访问**（API / DB / MCP） | 被攻破的 MCP 栈可能导致数据窃取、恶意代码执行 |
| **决策能力** | 看起来无害的指令可能被解读为完全不同的结果 |
| **上下文持久化** | 跨会话记忆产生新的数据保护需求 |
| **多 Agent 协作** | 攻破一个 Agent 可横向移动到其他系统 |

**两个新概念**：
- **爆炸半径（Blast Radius）**：出问题时的潜在损害范围。只读单个 DB 的 Agent vs. 有云管理员权限的 Agent，安全投入应匹配暴露程度。
- **最小代理权（Least Agency）**：OWASP 新术语，把最小权限延伸到 Agent。不只约束访问什么，还限制工具能做什么、多频繁、在哪里。

## 五大当前威胁

### 1. 提示注入与指令操控
- **直接注入**：构造输入覆盖系统指令，编码绕过过滤器，对抗性后缀。研究显示算法化方法可达 100% 攻击成功率，且可跨模型家族迁移。
- **间接注入**：把恶意指令嵌入 Agent 会处理的外部数据（网页、邮件）。**Microsoft Research 确认，LLM 无法可靠区分信息性上下文和可执行指令。**

### 2. 工具和资源滥用
- **工具中毒**：攻击者入侵 MCP 工具描述符。**第一个有记录的野外恶意 MCP 服务器冒充合法邮件服务，暗中复制所有发出邮件。**
- **工具链攻击**：骗 Agent 把合法工具以有害顺序组合（如 CRM + 邮件工具串联窃取客户数据）。因为每条命令通过可信二进制文件在有效凭证下执行，主机端监控看不到恶意软件。
- **资源耗尽**：循环放大让 Agent 反复调用高成本 API，造成 DoS 或账单飙升。

### 3. 身份与权限滥用
- **无范围权限继承**：高权限 Agent 委派任务时没做最小权限约束。
- **困惑代理人**：被攻破的低权限 Agent 向高权限 Agent 转发看似合法指令，后者直接执行而未验证原始用户意图。多 Agent 协作场景放大此问题。
- **基于记忆的权限留存**：Agent 缓存凭证未做记忆分段，攻击者可跨会话提升权限。

### 4. 供应链和依赖风险
- **模型供应链**：被投毒权重和污染微调数据引入后门。**Anthropic 研究表明，只需 250 个恶意文档就能在 6 亿到 130 亿参数 LLM 中植入后门，且后门在 SFT + RLHF 安全训练后仍然存在。**
- **工具供应链**：MCP 服务器、API 集成和 Agent 框架。PyTorch 依赖混淆攻击演示了恶意包如何在安装时窃取 SSH 密钥。安全研究人员在主要平台上发现了约 100 个恶意 AI 模型。

### 5. 记忆和上下文投毒
- **持久性**：植入到 Agent 记忆中的恶意指令危害当前和所有未来会话。
- **RAG 投毒**：通过被投毒数据源向向量数据库注入恶意内容。
- **长期记忆漂移**：摘要或同伴 Agent 的反馈逐步偏移存储知识，因为没有单个改变看起来是恶意的，很难检测。

## 六大安全能力域（三级框架）

每个能力域有 Foundation / Enterprise / Advanced 三级，下一级预期会成为上一级标准。

### 1. Agent 身份与认证
- **Foundation**：唯一标识符 + 密码学根基。**静态 API 密钥和共享服务账户密码是 AI 辅助攻击者最先找到的东西，即使在 Foundation 级别也不是合法入口。**
- 如果现在用带轮换策略的 API 密钥，把它当作已知缺口——对 AI 辅助攻击者来说轮换凭证提升的成本微乎其微。

### 2. 访问控制和权限管理
- Agent 只应拥有与角色相关的权限（邮件起草 Agent 不需要访问财务文件共享）。
- 对处理网页内容、文档或任何不可信输入的 Agent，**沙箱应被视为必需而非愿景**。

### 3. 可观测性和审计
- 在做其他检测投入之前，先度量两件事：**驻留时间**（异常发生到人类知晓的时长）和**覆盖率**（实际被调查的告警比例）。

### 4. 行为监控与响应
- **自动化事件周围的事务性工作，不要自动化决策。** 模型做笔记、捕获证据、起草事后报告；人类做遏制决策、披露决策和客户沟通决策。

### 5. 输入验证和输出控制
- 输入清洗不能从传统技术直接搬到 Agent——SQL 注入有明确模式，Agent 的输入是自由形式的。
- **聚光灯技术（Spotlighting）**：利用已知 schema 帮助 LLM 区分系统指令和用户输入，将间接注入成功率从 >50% 降到 <2%（Microsoft）。
- **宪法分类器（Constitutional Classifiers）**：Anthropic 方法在测试中阻止了 95% 的越狱尝试。

### 6. 完整性和恢复
- 把"启用自动更新"和"部署前验证签名"视为互补而非矛盾。
- **影子 AI** 是特别风险：员工在 IT 不知情下采用 LLM 工具，绕过框架中的所有控制。

## 八步实施工作流

| Phase | 核心行动 |
|---|---|
| 1. 识别需求 | 对齐监管要求、运营目标、约束条件；让安全/法务/合规/业务达成一致 |
| 2. 管理供应链风险 | AI-BOM 追踪模型来源；OpenSSF Scorecard 评估依赖健康度；自运行/签名 MCP 服务器 |
| 3. 定义 Agent 边界 | 唯一身份、批准/禁止动作白名单、升级触发器、范围限制、爆炸半径识别 |
| 4. 防御提示注入 | 将所有自然语言输入视为不可信；聚光灯技术；宪法分类器；限制 Agent 系统的攻击面 |
| 5. 保护工具访问 | 默认拒绝工具白名单；能力限制（只读 vs 读写）；参数验证；沙箱执行；审批升级 |
| 6. 保护 Agent 凭证 | 短命 token（分钟计）；硬件绑定凭证；每个实例唯一凭证；显式 Agent 间信任边界；JIT 访问 |
| 7. 保护 Agent 记忆 | 会话和用户间严格隔离；上下文完整性哈希验证；TTL 自动过期未验证记忆 |
| 8. 度量真正重要的东西 | 驻留时间 + 覆盖率；可解释性；行为一致性；检测速度（目标：关键系统 1 小时内检测到） |

## 防御运营：以自主威胁的速度运行

当漏洞利用在补丁发布几小时内出现，需要几天的响应流程就太慢了。

**答案不是把人从环里移除，而是把人从事务性工作上移到决策上。**

- **在告警队列前面放模型**：每条告警在人类看到之前都自动产出结构化处理意见。从一条高误报率的规则开始，跑两周对比人工审查员。不要试图一次自动化整个队列。
- **Agentic SOAR**：下一代 SOAR 增加对新情况的自适应能力，在几秒钟内应对恶意 AI 驱动攻击。
- **MITRE ATT&CK 映射检测覆盖**：知道能检测哪些技术比笼统"改善检测"更有用。用 Atomic Red Team 跑测试——这是一个下午的练习。
- **五个同时发生的事件桌面推演**：标准推演假设一个 CVE，跑一个同周五个的版本。围绕电子表格的工作流跟不上。
- **提前建立紧急变更程序**：提前决定谁能授权下线服务、轮换凭证、阻断网络路径，需要什么证据。演练授权路径。
- **对防御型 Agent 也要验证**：攻破防御型 Agent 的攻击者获得强大能力。防御型 Agent 也应最小权限运行，自动响应需人工审批高影响决策。

---

> **结论**：身份支持归因和访问控制。可观测性揭示发生了什么。行为监控检测异常。输入输出控制在边界阻止攻击。完整性保护支持恢复。防御运营以威胁的速度运行。跳过任何一项，攻击者就会利用那个缺口。
