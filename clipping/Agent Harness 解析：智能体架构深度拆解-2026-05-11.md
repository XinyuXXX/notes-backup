## 核心命题

LangChain 只改了包裹 LLM 的基础设施，模型权重完全没动，在 TerminalBench 2.0 上从 30 名开外直接跳到第 5。另一个研究项目让 LLM 自己优化基础设施，通过率达到 76.4%，超过了人工设计的系统。

**问题不在模型，在模型周围的一切。**

LangChain 的 Vivek Trivedy：**如果你不是模型本身，你就是 Harness。**

## 什么是 Agent Harness

Harness 是包裹 LLM 的完整软件基础设施：编排循环、工具、记忆、上下文管理、状态持久化、错误处理、安全护栏。

Anthropic 在 Claude Code 文档里直接写明：SDK 就是「驱动 Claude Code 的 agent harness」。

**关键区分**：「agent」是涌现出来的行为——有目标、会用工具、能自我纠正的实体。Harness 是产生这种行为的机器。当有人说「我做了一个 agent」，他们其实是做了一个 harness，然后把它对准了一个模型。

**Beren Millidge 的类比**（2023）：裸 LLM 是没有内存、没有硬盘、没有 I/O 的 CPU。
- 上下文窗口 = 内存（快但有限）
- 外部数据库 = 硬盘（大但慢）
- 工具集成 = 设备驱动
- Harness = 操作系统

我们重新发明了冯·诺依曼架构，因为这是任何计算系统的自然抽象。

## 三个工程层级

- **提示词工程**：设计模型接收的指令
- **上下文工程**：管理模型看到什么、什么时候看到
- **Harness 工程**：包含前两者，再加上完整的应用基础设施——工具编排、状态持久化、错误恢复、验证循环、安全执行、生命周期管理

## 生产级 Harness 的 12 个组件

### 1. 编排循环
TAO 循环（思考-行动-观察），即 ReAct 循环。机制上往往只是一个 while 循环，复杂性藏在循环管理的所有东西里，而不是循环本身。Anthropic 把运行时描述为「笨循环」，所有智能住在模型里，Harness 只管理轮次。

### 2. 工具
工具是 agent 的手。以 schema 形式定义（名称、描述、参数类型）注入上下文。工具层负责注册、schema 验证、参数提取、沙盒执行、结果捕获，以及格式化为 LLM 可读的观察结果。Claude Code 提供六类工具：文件操作、搜索、执行、网络访问、代码智能、子 agent 生成。

### 3. 记忆
多时间尺度运作：
- **短期**：单次会话内的对话历史
- **长期**：跨会话持久化——Anthropic 用 CLAUDE.md + 自动生成的 MEMORY.md；LangGraph 用命名空间 JSON Store；OpenAI 支持 SQLite/Redis 支持的 Session

Claude Code 三层层级：轻量级索引（约 150 字符，始终加载）→ 按需拉取的详细主题文件 → 只通过搜索访问的原始记录。关键设计原则：agent 把自己的记忆视为「提示」，行动前对照实际状态进行验证。

### 4. 上下文管理
**上下文腐烂**：关键内容落在窗口中间位置时，模型性能下降超过 30%（Chroma 研究，斯坦福「迷失在中间」论文印证）。即使是百万 token 的窗口，随着上下文增长，指令遵循能力也会退化。

生产级策略：
- **压缩**：接近上限时摘要对话历史（Claude Code 保留架构决策和未解决 bug，丢弃冗余工具输出）
- **观察屏蔽**：JetBrains Junie 隐藏旧工具输出，但保留工具调用可见
- **即时检索**：维护轻量级标识符，动态加载数据（Claude Code 用 grep/glob/head/tail，而不是加载完整文件）
- **子 agent 委托**：每个子 agent 大范围探索，只返回 1000–2000 token 的压缩摘要

Anthropic 目标：找到能最大化期望结果概率的**最小高信号 token 集合**。

### 5. 提示词构建
分层组装：系统提示 + 工具定义 + 记忆文件 + 对话历史 + 当前用户消息。重要上下文放在提示词开头和结尾（「迷失在中间」的发现）。OpenAI Codex 有严格优先级栈：服务器系统消息 > 工具定义 > 开发者指令 > 用户指令（级联 AGENTS.md，32 KiB 上限）> 对话历史。

### 6. 输出解析
现代 Harness 依赖原生工具调用，模型返回结构化 tool_calls 对象。逻辑简单：有工具调用 → 执行并循环；没有工具调用 → 最终答案。

### 7. 状态管理
LangGraph 将状态建模为流经图节点的类型字典，用 reducer 合并更新，超步边界触发检查点，支持中断后恢复和时间旅行调试。Claude Code 采用不同方式：**git 提交作为检查点**，进度文件作为结构化草稿纸。

### 8. 错误处理
**关键数据**：每步成功率 99% 的 10 步流程，端到端成功率仍然只有约 90.4%。错误快速累积。

LangGraph 四种错误类型：瞬时错误（带退避重试）、LLM 可恢复错误（把错误作为 ToolMessage 返回让模型调整）、用户可修复错误（中断请求人工输入）、意外错误（向上冒泡调试）。Stripe 生产 Harness 重试上限设为 2 次。

### 9. 护栏与安全
OpenAI SDK 三个层级：输入护栏、输出护栏、工具护栏（每次工具调用都运行）。「断路器」机制在触发时立即停止 agent。

Anthropic 架构上将权限执行与模型推理分离：模型决定尝试什么，工具系统决定允许什么。Claude Code 独立门控约 40 个离散工具能力，三阶段：项目加载时信任建立 → 每次工具调用前权限检查 → 高风险操作明确用户确认。

### 10. 验证循环
**玩具 demo 与生产 agent 的分水岭。** Anthropic 推荐三种验证方式：基于规则的反馈（测试/lint/类型检查）、视觉反馈（Playwright 截图用于 UI 任务）、LLM 作为评判者（独立子 agent 评估输出）。

Claude Code 创建者 Boris Cherny：给模型一种验证自身工作的方式能将质量提升 **2–3 倍**。

### 11. 子 Agent 编排
Claude Code 三种执行模型：Fork（父上下文字节级复制）、Teammate（独立终端面板，通过文件邮箱通信）、Worktree（每个 agent 独立 git 工作树和隔离分支）。OpenAI SDK 支持 agent 作为工具（有界子任务）和移交（专家接管完整控制权）。LangGraph 将子 agent 实现为嵌套状态图。

## 循环逐步演练

1. **提示词组装**：系统提示 + 工具 schema + 记忆文件 + 对话历史 + 当前消息；重要内容放首尾
2. **LLM 推断**：发送给模型 API，返回文本 / 工具调用请求 / 两者都有
3. **输出分类**：纯文本 → 结束；工具调用 → 执行；移交 → 更新当前 agent 重新开始
4. **工具执行**：验证参数 → 检查权限 → 沙盒执行 → 捕获结果（只读并发，写入串行）
5. **结果打包**：格式化为 LLM 可读消息，错误作为错误结果返回让模型自我纠正
6. **上下文更新**：追加到对话历史，接近上限时触发压缩
7. **循环**：返回第 1 步，直到终止

**终止条件**：无工具调用的响应 / 超过最大轮次 / token 预算耗尽 / 护栏断路器 / 用户中断 / 安全拒绝。

## Ralph Loop（长任务跨窗口模式）

两阶段模式，用于跨越多个上下文窗口的长时间运行任务：
1. **初始化 agent**：建立环境（初始化脚本、进度文件、功能列表、初始 git 提交）
2. **编码 agent**：每个会话读取 git 日志和进度文件定位自身 → 选择最高优先级未完成功能 → 完成后提交并写入摘要

文件系统在上下文窗口之间提供连续性。
